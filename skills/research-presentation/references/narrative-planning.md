# Narrative planning for research presentations

## Communication job

Write one sentence describing the audience outcome and central takeaway. A presentation is not a paper's table of contents; it is a sequence of resolved questions.

## Arc selection

| Audience / venue | Recommended arc |
|---|---|
| Journal club | question → gap → method → evidence → boundary → discussion |
| Lab meeting | decision/problem → current evidence → interpretation → next experiment |
| Conference | problem → contribution → method → strongest result → implication |
| Thesis defense | research program → contribution 1…n → integrated conclusion → limitations |
| Teaching seminar | motivation → concept → worked example → application → recap |

## Ghost-deck test

Write one takeaway sentence per slide before layout. Each slide must have one narrative job, one main claim, one evidence anchor, one visual anchor, and one transition. If two adjacent slides have the same job, merge them or give the second slide a narrower diagnostic question.

Use action titles: state what the audience should conclude, not merely the topic. “The model reproduces the observed phase boundary” is stronger than “Validation.”

## Progressive disclosure

For a complex mechanism, move from overview to diagnostic detail: system → key contract → evidence → boundary. Vary the layout every two or three slides while keeping the same theme, margins, title hierarchy, and footer system.

## Speaker notes

Notes are for the spoken bridge, not a copy of the slide. Start with the transition, explain the visual in the order the audience should read it, state the caveat, and finish with a `[Sources]` block. Keep notes source-grounded and do not add unsupported interpretation merely to make the talk sound complete.
